## Project Overview

3dModelsBrowser is a static web app that serves as a searchable gallery for a personal 3D model collection. It reads metadata produced by Orynt3D (the desktop cataloguing app) and makes it browsable from anywhere via Netlify.

**Personal tool.** No model data or images in git -- `src/data/*.json` +
`public/thumbnails|detail/` are generated by `npm run data` from the NAS and
committed as a snapshot; Netlify builds from that snapshot with no NAS access.

## Where This Lives in the Pipeline

```
Raw subscription downloads
        ↓
  orynt3d-pipeline (reorganizes files into Orynt3D folder structure)
        ↓
  Orynt3D desktop app (scans, previews, writes config.orynt3d per model)
        ↓
  3dModelsBrowser ← this project
  (scan-nas.mjs reads config.orynt3d files → data/raw/models.json → build-filter-index.mjs → Astro gallery → Netlify)
```

## Architecture

```
src/
  pages/
    index.astro          # gallery shell; hosts the filter island
    m/[id].astro          # per-model detail page (getStaticPaths -> detail-paths.ts)
  layouts/Base.astro      # shared shell + <ClientRouter /> (View Transitions)
  components/GalleryIsland.tsx  # the single client:load island (panel + windowed grid)
  lib/                    # pure, unit-tested logic:
    filter-engine.ts      #   bitsets + facet counts (D4)
    use-gallery.ts        #   island state: FilterState + engine + URL sync
    url-state.ts          #   FilterState <-> query string (D8)
    grid-layout.ts        #   column/row/scroll geometry for the windowed grid
    detail-paths.ts       #   getStaticPaths for /m/[id]
  data/
    filter-index.example.json   # COMMITTED shape doc (hand-written)
    filter-index.json / details.json  # generated; gitignored until the real npm run data
scripts/
  scan-nas.mjs            # walks NAS config.orynt3d -> data/raw/models.json (docs/nas-scan-spec.md)
  make-thumbnails.mjs     # sharp: sourceImage -> public/thumbnails|detail/<id>.webp (400/900px)
  build-filter-index.mjs  # data/raw/models.json -> src/data/*.json  (no NAS; buildIndex() is pure)
  dev-bootstrap-raw.mjs   # THROWAWAY: legacy snapshot -> data/raw/models.bootstrap.json
  lib/ { recency.cjs, model-resolve.mjs, thumbnail-paths.cjs }
data/raw/                 # GITIGNORED working artefacts
tests/fixtures/           # build-nas-fixture.mjs (temp NAS tree), raw-models.mjs
public/thumbnails/ detail/ # COMMITTED WebP renditions (once npm run data has run)
example configs/           # reference config.orynt3d samples
```

## Tech Stack

- **Astro 7 (static)** + one **Preact + `@preact/signals`** island (search/filter/grid)
- Row windowing hand-rolled over `grid-layout.ts` (not `@tanstack/virtual` -- uniform heights)
- **`sharp`** (local only) for WebP thumbnails; images referenced by plain `<img src>` (no `astro:assets`)
- **Vitest** + `@testing-library/preact`; `type: "module"`, legacy scripts are `.cjs`
- **Netlify** -- `npm run build` = `astro build` only, reads the committed snapshot, no NAS

## Pipeline

```
NAS  -> scan-nas.mjs        -> data/raw/models.json          (gitignored)
     -> make-thumbnails.mjs -> public/thumbnails|detail/*.webp (committed)
     -> build-filter-index.mjs -> src/data/{filter-index,details}.json (committed)
     -> astro build         (no NAS)
```

`npm run data` runs the first three; **commit the outputs** -- that is the snapshot Netlify builds from.

## Deployment

Netlify builds via GitHub pull hook (push to `main` = auto-deploy). `npm run build` = `astro build` only -- it reads the committed `src/data/*.json` + `public/thumbnails|detail/` snapshot and never contacts the NAS, so the build environment needs nothing special. Refreshing the snapshot (`npm run data`) is a local, NAS-connected step whose outputs are committed.

Branch strategy: `feat/astro-rewrite` gets a Netlify **branch deploy** for preview; production stays on the old build until merge.
